# MT-001 · MarsTube maintenance and TV build — candidate

Status: **proposed, not released**. Baseline:
`fix/mars-glass-inapp-no-logo-32-68-11` (Mars-32.68.11,
`de.equiummc.mars.smarttube`). This is a source branch, **not proof that
32.68.11 is installed or passed real-device smoke tests**.

## Why the baseline is not `mars/stable` yet

At initial inspection `mars/stable` declared `Mars-32.68.1`, while the
latest functional native-Leanback plus blue-glass candidate declares
`Mars-32.68.11`. Replacing the candidate with the older branch would
silently lose intended work. No release branch is promoted by MT-001.

## Upstream sync

Workflow: `.github/workflows/upstream-watch.yml`.

- Queries the latest published **stable** tag of
  `yuliskov/SmartTube`, fetches that exact tag, and compares the Git
  ancestry against the Mars candidate.
- When newer, attempts a non-fast-forward merge in a separate
  `mars-upstream/stable-<tag>` branch and proposes a pull request
  **targeting the candidate**.
- Existing pull requests/issues are deduplicated by title.
- Merge conflict, insufficient GitHub token rights, or inability to create
  a PR results in an issue with instructions where possible.
- **No auto-merge, tag, release, update-feed edit, TV install, or signing.**
- Scheduled GitHub Actions workflows execute from the repository's default
  branch only. This replacement monitor is **not active** while it lives
  only on the MT-001 feature branch. Promotion requires independent review.

The preview target must change to a verified `mars/stable` only after that
branch intentionally contains the approved MarsTube baseline. Do not
silently promote a candidate on the strength of passing CI alone.

## Native TV validation

Workflow: `.github/workflows/mars-tv-validation.yml`.

- Uses `actions/checkout` with `submodules: recursive`.
- Requires the actual `SharedModules/core_settings.gradle`,
  `MediaServiceCore/core_settings.gradle`, and ExoPlayer Gradle settings
  before compilation. No symbolic links or shared broken .git files.
- Runs `python3 scripts/mars/verify_fork.py --require-submodules`.
- Builds `:smarttubetv:assembleStstableDebug` and runs
  `:common:testStstableDebugUnitTest`.
- Stores only a short-lived **test** APK in GitHub Actions artifacts.
  This is not a production or independently signed release.

These static guardrails check package identity, native navigation,
absence of the experimental second rail and in-app M badge, blue glass
theme registration, dependency declarations, and fork-scoped update
configuration. **They cannot prove playback, settings, authentication,
remote-control focus, or performance on Android TV.** Such checks need
real-device manual acceptance.

## MT-002 blockers: releases and updater

The installed app's stable-update resource is
`common/src/ststable/res/values/update_urls.xml`. It refers to
`https://raw.githubusercontent.com/equiummc/mars-smarttube/master/mars/updates/stable.json`.
That file **was absent from master** when MT-001 was prepared. A
candidate manifest on a feature branch still describes `Mars-32.68.1`
and has no installable version-specific APK URL. Existing update checks
must therefore **not** be presented as a working release pipeline.

Before any release:

1. Determine the Android signing certificate SHA-256 fingerprint of the
   actually **installed** `de.equiummc.mars.smarttube`. Never request or
   print private keystore bytes.
2. Choose a permanent signing setup and test an `adb install -r`
   upgrade from the current installation with retained app data.
   A mismatch requires an explicit migration decision, not silent
   uninstall or data loss.
3. Build, sign and independently verify universal/ABI APKs. Record
   SHA-256, certificate fingerprint, size, source commit and
   SmartTube upstream base. Use protected GitHub Actions secrets.
4. Publish first as a **draft** release; gate promotion on Android-TV
   tests (home, games, search, settings, account, playback, SponsorBlock,
   back navigation and performance).
5. Only after publication, generate and advance a valid, atomically
   updated `stable.json` manifest, never pointing to an unsigned,
   development or incompatible APK.
6. Preserve a known-good release and a documented way to restore it
   without silently deleting preferences.
7. Decide repository visibility and distribution topology separately:
   private source is compatible with CI, but unauthenticated Android TVs
   need a deliberately reachable update manifest/APK endpoint.

## Versioning

Track the MarsTube product version and SmartTube upstream tag/commit
**separately**. Monotonically increase Android `versionCode` for every
released MarsTube APK. Alpha/beta/stable semantics and exact release tag
syntax belong to a future explicit release policy; MT-001 does not
change existing installed version codes or app identity.
